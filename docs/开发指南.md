# 开发指南

> 环境要求、跑起来的路径、以及每个交付物用哪些命令验证。
> 下面每条命令与产物都在 2026-10-18 于 macOS (arm64) 实测过，输出记在
> `docs/实现现状.md`。最后核实：2026-10-18。

## 一、环境

| 工具 | 实测版本 | 用途 |
|---|---|---|
| Rust / Cargo | cargo 1.98.1 | 服务端 |
| Node.js | v26.11.0 | 控制台 |
| Flutter | 3.47.7 (stable) | 骑手端 |

`~/.cargo/bin` 默认不在 PATH 里，跑 Rust 命令前先：

```bash
export PATH="$HOME/.cargo/bin:$PATH"
```

`client/pubspec.yaml` 要求 Dart SDK `>=3.4.0 <4.0.0`、Flutter `>=3.22.0`。

## 二、跑起来

服务端没有配置文件，全部走环境变量（完整清单见 `docs/API.md` §四）。

### 最小可跑：服务端 + 控制台

```bash
export PATH="$HOME/.cargo/bin:$PATH"
cd server
RIDER_SIM_ALLOW_CONTROL=true cargo run
```

然后浏览器打开 **http://127.0.0.1:8080/** —— 控制台已经打进二进制，
不需要单独起前端（`server/src/net/ws.rs:85`）。

### 控制台热更新开发

改 `server/console/` 的源码时需要 Vite 开发服务器：

```bash
cd server/console
npm ci
npm run dev            # http://127.0.0.1:5173，代理 /ws /api /healthz → 127.0.0.1:8080
```

代理目标写死在 `server/console/vite.config.ts:31-34`，所以**服务端要先起来**。

### 骑手端

```bash
cd client
flutter pub get
flutter run            # Android / iOS（真机或模拟器）或 Chrome；平台目录只有 android/ios/web，跑不了桌面
```

### 让手机连上（真人骑手）

手机和服务器不在同一台机器时，需要告诉烽火台"骑手该连哪个地址"，
否则二维码里是本机回环地址：

```bash
RIDER_SIM_PUBLIC_ADDR=<主机> cargo run           # 主机 或 主机:端口
RIDER_SIM_PUBLIC_URL=wss://example.com/ws cargo run   # 完整地址，配了就以它为准
```

也可以运行时临时改：`POST /api/join`（**只在本次运行内有效，不落库**）。

然后在控制台「骑手接入」页建号 → 扫二维码 → 骑手端自动填好地址与账号。
手填也行，默认 `ws://127.0.0.1:8080/ws`。

> 扫码要相机权限，Android / iOS 需要原生工程。三个平台目录
> （`client/android/`、`client/ios/`、`client/web/`）当前**都已生成**，
> 可以直接 `flutter run` 到设备或模拟器。

## 三、验证命令

改完代码按下面对应交付物各跑一遍。

### Rust 服务端

```bash
cd server
cargo test --workspace      # 全量测试
cargo fmt --all --check     # 格式
cargo clippy --all-targets  # lint
```

分层约束由 `server/tests/layering.rs` 在 `cargo test` 里强制，见 `AGENTS.md` §三。

### 控制台

```bash
cd server/console
npm run typecheck    # tsc --noEmit
npm run build        # tsc --noEmit && vite build
```

`npm run build` 的产物落 `server/static/`，Vite 先把 `index.html` 写到那里，
`vite.config.ts` 里的 `emit-console-html` 插件在 `closeBundle` 时把它重命名为
`console.html`（`vite.config.ts:20-24`）。

**只有重新 build，`cargo run` 起来的服务端才会带上新的控制台** —— 控制台是
`include_str!` 编译进二进制的，不是运行时读盘。

### 骑手端

```bash
cd client
flutter analyze
flutter test         # test/login_link_test.dart、test/order_card_smoke_test.dart
```

## 四、常见卡点

| 症状 | 原因 / 处理 |
|---|---|
| 控制台改了没生效 | 没 `npm run build`，或 build 完没重启 `cargo run` |
| `RIDER_SIM_ADDR 不是合法地址` | 环境变量格式必须是 `主机:端口`（`server/src/main.rs:98`） |
| 抢不到控制权 | 未配 `RIDER_SIM_CONTROL_TOKEN` 且没开 `RIDER_SIM_ALLOW_CONTROL` → `403 CONTROL_DISABLED` |
| 手机连不上 | 二维码里是本机地址，缺 `RIDER_SIM_PUBLIC_ADDR` / `RIDER_SIM_PUBLIC_URL` |
| 地图整体偏几百米 | 坐标系与底图没成对切换，或手机 GPS 的 WGS-84 没换算就上报。见 `AGENTS.md` §五 |
| SQLite 打不开 | 会**自动降级为内存库**继续跑，不是崩溃（`RIDER_SIM_DB`） |
| LLM 没反应 | 只有 `RIDER_SIM_LLM=true` 会在启动时启用 brain；控制台设的 Key 不会自动启用。见 `AGENTS.md` §六 |
| 高德路径没走 | 未配 Key 时静默降级为抖动直线轨迹，不报错 |
