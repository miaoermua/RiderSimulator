## 二、唯一的失败测试（已定位根因，**不是产品缺陷**）

`server/tests/acceptance.rs` 的
`speed_multiplier_only_changes_real_time_pacing` 失败：

```
assertion `left == right` failed: 1x 的 tick 间隔不对
  left: 60000
 right: 1000
```

根因：该测试从 `SimConfig::default()` 出发逐个断言倍率档的 tick 间隔，
但 `SimConfig::default()` 的 `realtime` 是 **`true`**（`config.rs:527`），于是
`tick_interval_ms()`（`server/src/sim/config.rs:579-588`）走了实时档分支，
返回 `REALTIME_TICK_MS`（`config.rs:13` = `60_000`）而不是 `1000 / multiplier`。

实现是对的，是测试过期了——实时档功能后加，把 `default()` 的 `realtime` 变成了
`true`，这个更早写的验收测试没跟着调整。对照：同仓库的单元测试
`config.rs:616 tick_interval_scales` 就先做了 `c.realtime = false`，因此通过。

修法（供后续处理，本文不代为改动）：在 `acceptance.rs:277` 的循环之前（紧接
276 行的 `let mut cfg = SimConfig::default();`）加 `cfg.realtime = false;`。
这属于改测试代码，建议独立成一个提交，别和功能改动混在一起。

均为既有代码遗留，与近期功能无关。「出现在」列区分 `cargo clippy --lib`（不含
`#[cfg(test)]` 代码）与 `--lib --tests`：

| 位置 | 警告 | 出现在 |
|---|---|---|
| `src/app.rs:646:29` `:647:27` `:650:28` | deref which would be done by auto-deref | lib、lib test |
| `src/app.rs:3516` `:3517` | field assignment outside of initializer（同一个实例：`LlmConfig::default()` 之后逐字段赋值） | lib、lib test |
| `src/llm/brain.rs:498:10` | `Err` variant 过大 | lib、lib test |
| `src/llm/client.rs:1257:19` | unneeded `concat!` | 仅 lib test（`cfg(test)` 自 `:866`） |
| `src/sim/config.rs:617` `:619` | field assignment outside of initializer | 仅 lib test（`cfg(test)` 自 `:590`） |
| `src/sim/tick.rs:1050` `:1051` | field assignment outside of initializer | 仅 lib test（`cfg(test)` 自 `:915`） |

每个 lint 实例都同时列出 `let mut … = Default::default()` 那一行和紧随其后的赋值行，
所以成对出现。`tests/*.rs`、`src/bin/*.rs`、`src/main.rs` 全量重编后**没有**告警。
上面的 "5 duplicates" 是**冷缓存全量重编**的计数；热缓存下 cargo 汇总里的
duplicate 数会变小，但告警清单本身不变。

> `config.rs:619` 正是本文 §二 里 `tick_interval_scales` 用来关掉实时档的那一行——
> 也就是说 clippy 嫌的写法恰好是修那个失败测试所必需的写法。动本文 §二 时留意这两处

### 消息信封与设计文档不一致（既有决策）

`docs/技术设计.md:318` §4.2 规定信封为 `{type: req|res|evt, id, action, payload}`；
实现用的是 `#[serde(tag = "type")]` 的 `ClientMessage` + `Ack` / `Envelope`
（`protocol.rs:40`、`ws.rs:199`）。控制台与骑手端都建立在当前形状上。
这条**尚未在两份设计文档里更正**，属于待决事项（改文档 or 迁移代码）。

### 控制协议相对规格的缺口

`RIDER_SIM_SEED` 只能在启动时经环境变量设定（`server/src/main.rs:13,40`），
运行期**没有**改种子的控制消息。这是刻意的：中途改种子会破坏
"同种子两次运行结果一致"这条验收标准（`技术设计.md:693, 712`）。
它属于还不存在的"重开一局"功能，不是漏实现。
