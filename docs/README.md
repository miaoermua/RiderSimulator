# 文档导航

本仓库的文档分成三类，**不要混着读**：意图、事实、约定。

## 入库文档

| 文件 | 讲什么 | 什么时候读 |
|---|---|---|
| [`../README.md`](../README.md) | 项目是什么、能干什么 | 第一次接触 |
| [`../AGENTS.md`](../AGENTS.md) | 给 AI 编码代理的约定：硬约束、契约同步点、已知陷阱 | **改代码前必读** |
| [`../DISCLAIMER.md`](../DISCLAIMER.md) | 独立实现声明、非逆向工程说明、人身安全与保险边界、GPL 许可范围与闭源责任、免责与用途边界 | 关心来源与合规时 |
| [`技术设计.md`](技术设计.md) | **意图**：架构决策、协议设计、内核与高德接入、验收标准 | 想知道为什么这么设计 |
| [`玩法设计.md`](玩法设计.md) | **意图**：经济、天气、速度风险、订单、AI、任务、界面规格、数值表 | 想调平衡或加玩法 |
| [`实现现状.md`](实现现状.md) | **事实**：实测验证结果、失败测试、契约缺口、数据量差距 | 想知道现在到底做到哪了 |
| [`API.md`](API.md) | **事实**：HTTP 路由全表、WS 入口、鉴权、环境变量 | 对接外部工具或改接口 |
| [`开发指南.md`](开发指南.md) | **操作**：环境、跑起来、验证命令、常见卡点 | 上手开发 |

## 两份设计文档的性质

`技术设计.md` 与 `玩法设计.md` 头部都标着 **v1.0 · 2026-10-06**，写的是**设计意图**。
它们会落后于代码——已知并保留的偏差记录在 `实现现状.md`。读的时候注意区分
"规格说要这样" 和 "代码现在这样"。

其中 `技术设计.md` §二 目录结构是**尚未跟进代码的设计原稿**（写了从未存在的
`desktop/` Tauri + Vue 方案、`rider/` 目录名等），**未代为改写**，待决。
实际结构一律以 [`实现现状.md`](实现现状.md) §六 为准。

## 不入库的内容

`docs/cache/` 整个目录在 `.gitignore` 里，**不随仓库分发**，放的是设计过程稿、
竞品调研和 agent 本地缓存：

```
docs/cache/
├── 三层AI架构设计.md
├── LLM协议设计.md
├── 算法行为手册.md
├── 手机端细节-活动导航指派单菜单.md
├── 竞品案例-众包骑手端.md
├── 目录重构方案.md
└── status.md
```

这些是**草稿与调研**，不是承诺实现的规格，也不保证与代码一致。
`status.md` 是同主题的旧版状态记录，其结论已被 `实现现状.md` 取代。

> 竞品调研（`竞品案例-众包骑手端.md`）记录的是**公开可见的界面交互形态**观察。
> 本项目未对任何平台做逆向工程，边界见 [`../DISCLAIMER.md`](../DISCLAIMER.md) §三。
